# Trekkey 공학경진대회 10분 발표 플로우

## 발표의 한 문장

> Trekkey는 대학이 승인한 경험을 개인이 소유하고, 필요한 정보만 공개하며, 외부인이 로그인 없이 진위를 검증할 수 있게 하는 Credential 프로토콜·플랫폼입니다.

발표 제목은 **Merkle Proof 기반 개인정보 보호형 대학 활동 Credential 발급·검증 플랫폼**으로 통일한다.

## 발표 웹 조작법

- 주소: `/pitch`
- 운영 Credential 연결: `/pitch?credential={publicId}`
- 다음/이전: `→`, `←`, `Space`, `PageDown`, `PageUp`
- 타이머 시작·정지: `T`
- 발표자 노트: `N`
- 전체 화면: `F`
- 처음/마지막 장: `Home`, `End`
- 9분 20초부터 타이머가 노란색, 10분 초과 시 빨간색으로 바뀐다.

## 발표 전 탭 순서

1. `/pitch?credential={publicId}` — 첫 장, 전체 화면
2. `/participant/evidence` — 개인정보가 없는 데모 자료, 2/2 검수 완료
3. `/evidence` — 별도 관리자 프로필에서 같은 데모 완료 건과 이력 표시
4. `/participant/graduation` — 자가점검 실행 완료, 요약 영역 표시
5. `/verify/{publicId}` — 별도 대회 Credential의 검증 완료 화면 로딩
6. `/tamper-lab?mode=live&credential={publicId}` — 정상 Proof 화면 로딩
7. `/evidence-report` — 벤치마크 실행 완료

학생과 관리자 인증 쿠키가 충돌하면 일반 창에는 학생·공개 화면을, 별도 Chrome 프로필이나 시크릿 창에는 관리자 화면을 연다. macOS 전체 화면은 창을 다른 Space로 보내므로 두 창은 최대화만 하고, 탭·창 전환 키를 사전에 고정한다. 인증이 풀리면 무대에서 로그인하지 않고 발표 웹의 사용자 여정·구현 범위 장으로 복귀한다.

## 리허설 및 당일 체크리스트

1. 발표 하루 전과 시작 15분 전에 공개 가능한 `ANCHORED` Credential을 새로 선택한다. 문서에 특정 ID를 고정하지 않는다.
2. `/pitch?credential={publicId}`에서 운영 시연, 공개 검증, Tamper Lab 링크가 같은 ID를 전달하는지 확인한다.
3. 외부 증빙은 `검증 완료`, `2/2명`인 개인정보 없는 데모 자료를 선택한다.
4. 개인정보가 포함된 관리자 화면, 업로드 원문, 토큰, 브라우저 개발자 도구는 열지 않는다.
5. 네트워크가 3초 이상 지연되면 새로고침을 반복하지 말고 이미 로딩된 다음 탭 또는 발표 웹으로 즉시 이동한다.
6. 운영 Credential 실패 시 Tamper Lab의 결정적 fixture로 전환하되 “운영 체인이 아닌 로컬 계산 시나리오”라고 밝힌다.
7. 세 번의 리허설 목표는 `09:40 ± 10초`다. 남은 20초는 화면 전환 지연과 심사장 반응에 사용한다.

## 예상 질문과 20초 답변

### 블록체인이 왜 필요한가요?

대학 DB만으로도 발급은 가능하지만 외부 검증자가 같은 운영 주체의 응답을 다시 믿어야 합니다. Trekkey는 여러 Credential의 Root와 상태를 공개 원장에 고정해 승인 후 변경 여부를 기관 밖에서도 교차 확인하게 합니다.

### 대학이 거짓으로 승인하면요?

블록체인은 현실의 진실을 판정하지 않습니다. 담당자 승인과 2인 검수 같은 거버넌스가 사실성을 책임지고, Trekkey는 승인 이후 무결성과 현재 효력을 검증합니다.

### 개인정보가 공개되지 않나요?

학번, 이메일, 증빙 원문은 기관 서버에 남습니다. 외부 검증에는 사용자가 동의한 요약과 Proof만 제공하고, 체인에는 Root, 발급자, 상태만 기록합니다.

### Merkle Proof가 영지식증명인가요?

아닙니다. 공개된 leaf가 특정 Root에 포함됐다는 무결성 증명입니다. 저희는 ZKP라고 주장하지 않으며, 필요한 공개 범위를 줄이는 데이터 배치 정책과 함께 사용합니다.

### 1,000개 성능 수치는 무엇인가요?

현재 브라우저에서 1,000개 fixture의 해시, Merkle Tree, 중앙 Proof 생성·검증에 걸린 시간입니다. 네트워크, DB, 트랜잭션 확정 시간을 포함한 전체 TPS가 아닙니다.

### 기존 전자증명서와 차이가 무엇인가요?

PDF 한 장 발급에서 끝나지 않고, 기존 대학 업무의 확정 이벤트를 발급 원천으로 연결하며, 현재 효력과 변조 여부를 공개 Proof로 재검증할 수 있다는 점입니다.

### 졸업요건 결과가 공식인가요?

아닙니다. 현재는 학생이 업로드하거나 입력한 자료를 공식 근거와 정책 기준일에 맞춰 확인하는 자가점검입니다. 공식 판정은 학사 시스템 연동과 대학 승인 이후의 범위입니다.

### 서비스가 중단되면 검증할 수 있나요?

현재 공개 검증 화면은 서비스 API가 공개하는 payload와 Proof를 사용합니다. Root와 트랜잭션은 공개 원장에 남지만 완전한 독립 검증을 위해서는 공개 스키마와 증거 패키지의 장기 배포가 다음 운영 과제입니다.
